ROLE-BASED ORCHESTRATION

Explicit responsibilities, inspectable handoffs

Independent role modules cooperate through typed JSON events. Offline agents are deterministic; optional model analyst, reviewer and reporter use separate API exchanges.

Planner / 规划Break questions into supported fields and scope.
Retriever / 检索Retrieve only visible project sources.
Extractor / 提取Attach exact source spans and normalized units.
Reconciler / 仲裁Apply explicit revisions; keep unresolved disagreements.
Verifier / 核验Check quotations against original source offsets.
Reporter / 报告Expose facts, unknowns and human-review decisions.
Optional model roles: Analyst → Reviewer → Reporter. They may use the same underlying model; role separation does not imply independent experts. Model notes remain subject to human review.

Jinshi-informed engineering / 金石工程元素

The reference design reflects the publicly describable patterns of document-based knowledge work, role boundaries, evidence tracing and human review associated with the applicant's engineering background. It is independently implemented. No Jinshi source code, internal data, corporate branding or operational performance is reproduced.

Current boundaries

Eight supported field families and documented language patterns; PDF text-layer import, not OCR. Exact source-span verification is not a general semantic truth test. Role selection simulates visibility. Local logs are hash-linked but are not independently timestamped or tamper-proof. No external adoption is asserted.

Reproduction and contribution

Python 3.10+, standard-library core, optional pypdf. Run tests and evaluations from the README; inspect the English report, raw results and source manifest. AI-assisted code and documentation remain open for technical review.
